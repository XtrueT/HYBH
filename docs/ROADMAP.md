# H.Y.B.H PWA 迭代计划（v2 · 省心版）

> 更新：2026-10-15 · 依据用户定调全面修订（v1 中与哲学冲突的条目已作废，见第一节）
> 一句话定位：**这是一个「坚持助手」，不是「训练账本」。**

---

## 〇、产品哲学（本计划的宪法）

坚持训练本身已经很难，应用的任务是**替用户省心力**，而不是再多要一点数据。

1. **输入上限 = 一次点按。** 打卡是唯一的日常输入；任何需要"填写 / 记录 / 维护"的功能一律不做。
2. **过去不可改写。** 打卡记录只读 —— **禁止补卡、禁止回填**；错过了就是错过了，这正是记录的真实与分量。
3. **分析只基于已有数据。** 统计看板全部从打卡记录推导 —— 零新增输入，用户什么都不用填。
4. **计划变更走 AI。** 应用内不做手动编辑器 —— 把新需求发给 AI、粘回定制包，就是唯一的（也是零表单的）定制路径。
5. **应用多做事。** 里程碑庆祝、方向提醒、变更点标注 —— 这些都不需要用户做任何事。

## 一、明确砍掉（v1 计划中与哲学冲突的条目，作废）

| 砍掉 | 理由 |
|---|---|
| ~~体重记录 + 趋势线~~ | 用户自有体重秤 / 健康设备；这不是本应用该管的数据 |
| ~~组次 / 重量记录（渐进超负荷）~~ | 典型"健身账本"功能，输入量与维护成本最大 |
| ~~应用内计划编辑器~~ | **核实：应用内已有计划编辑器**（设置 → 计划管理 → 编辑/新建）。AI 仍是主推定制路径，编辑器保留不动 |
| ~~休息计时器~~ | 停车场：零输入但增 UI 复杂度，想清楚再捡 |

> 本 v2 计划因此**零 schema 变更** —— "省心"在数据层的体现：不动结构，只把已有数据变得好看、好用。

## 二、P0 · 看得见的历史与自动统计（全部零新增输入）

> 主题：用户只需要"点一下"，应用负责让他**看见自己的坚持**。

### 1. 当日详情（已存在 ✓）+ 弹层穿透修复（已完成 2026-10-15）
- 核实：`showDay()` + `#daypop` 弹层早已完整（计划名 / 逐个动作 ✓✗ / 餐清单 / 全勤日标记）—— v2 原条目与现状重复，撤下
- 本次实际修复的是它的**缺陷**：Popover 的 `::backdrop` 不拦截指针，关闭弹层的点击会同时触发底下元素的 onclick（误勾今日打卡）
- 修复方式：pointerdown 时记录弹层开合状态 → 该手势的 click 一律吞掉（热力图格子除外，可连续换看不同天）+ 250ms 时间戳兜底
- 只读原则不变：禁止补卡

### 2. 热力图卡改两态 ✓（已完成 2026-10-15）
- 问题（用户实测）：热力图展开占约 150px 高，把打卡主内容挤到屏幕外，用户经常被迫隐藏热力图
- 已实现：
  - **收起态（默认）**：一行摘要「连续 N 天 · 本月 x/y 天」—— 连击常驻主页，这就是每天最需要的"坚持反馈"
  - **展开态**：完整热力图（含月份标注）+「收起 ▴」
  - 状态记忆 `DB.settings.hmOpen`（默认收起），一次点按切换，无 schema 变更
  - **开关常驻热力图卡右上角（主导航上方）**：收起态「展开 ▾」/ 展开态「收起 ▴」，两种状态同一位置
- 主页高度预算：收起后今日页打卡区多出约 100px ≈ 2-3 行动作

### 3. 统计看板 ✓（已完成 2026-10-15，可选项 · 默认隐藏）
- 开关：设置 → 热力图卡「统计看板 显示/隐藏」（默认隐藏，`DB.settings.showStats`，向后兼容，无 schema 变更）
- 位置：展开态热力图下方
- 内容（全部由 `days` 推导，零输入）：**计划变更点时间轴**（planId 推导，用户点名："10/01 开始 哑铃增肌周 → 10/08 换 减脂循环周"）、逐月完成率条形（近 12 个月）

### 4. 里程碑庆祝 ✓（已完成 2026-10-15）
- streak 7/14/21/30/50/100/150/200/300/365：今日页头部自动出现「🔥 连续打卡 N 天」
- 非里程碑日不显示；只庆祝、不催促、不施压

### 5. 历史浏览设计结论（已评审）
- 保持现有「范围切换 近3/6/12 个月 + 横向滚动」—— 已覆盖一年，足够
- 更宏观的历史 → 展开态里的「逐月完成率」条形图（自动推导），看趋势比翻格子更合适
- ❌ 不做无限横向滚动（难定位、没有位置感）
- ❌ 不做年份下拉（为极罕见需求加控件不值）—— 出现真实需求再议

> **P0 全部完成（2026-10-18）**：穿透修复、滚动条、两态、图例、热区、统计看板、变更点、里程碑 ✓
> 全程零 schema 变更（仅 settings 新增 hmOpen/showStats 两个布尔字段，向后兼容）。

## 原则（每条功能开工前过一遍）

1. 这次交互需要用户"填写"什么吗？—— 需要，就不做
2. 这个数据用户非记不可吗？—— 不是，就不做
3. 应用能不能替他做？—— 能，就做成自动的
4. 纯本地优先；网页版与鸿蒙原生版同步演进
5. 遵守 UI 约定（强调色只表状态、无解释性文案、应用外壳、外链 ↗）
