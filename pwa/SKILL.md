# H.Y.B.H AI 定制工作流

把用户的自然语言需求转换为一份 **AI 定制包 JSON**，用户在 App「AI」页粘贴即可一键导入。

## 工作流

1. **收集需求**：目标（增肌/减脂/体态/体能）、身高体重、年龄、性别、目标体重、每周可训练天数、可用器材（哑铃重量/弹力带/徒手）、饮食预算或偏好、伤病史。缺失项用合理默认值并在输出前向用户复述假设。
2. **设计**：按下方「数据契约」构造 JSON。优先复用内置动作（见内置动作清单），只把库里没有的动作放进 `exercises`。
3. **校验**：输出前逐项自查——`kind` 必须是 `hybh-custom`；`plans.*.days` 恰好 7 项；`fig`/`part` 在枚举内；`exNames` 中的动作名要么在内置清单、要么在 `exercises` 里。
4. **输出**：一个完整 JSON（单独代码块），随后附 3-5 行要点说明（训练思路、饮食系数、注意事项）与免责声明。

## 数据契约（完整字段说明与示例）

### 顶层结构

```json
{
  "kind": "hybh-custom",
  "v": 1,
  "profile": "用户需求一句话摘要（≤50 字）",

  "exercises": [ { "name": "壶铃摆荡", "fig": "dead", "part": "臀", "equip": "壶铃", "sets": "3 × 15", "points": "髋部发力甩铃，下背保持中立。" } ],
  "plans": { "plan1": { "name": "居家增肌四周", "dir": "增肌", "days": [
    { "title": "上肢推", "exNames": ["俯卧撑", "肩上推举", "哑铃飞鸟"] },

    { "title": "上肢拉", "exNames": ["单臂划船", "哑铃弯举", "平板支撑"] },
```

### 字段约束

- **settings**（可选）：height 100-250 cm；weight 需落在 **BMI 12-70** 内（这是防误输入的合理范围，覆盖极端体型，不代表健康标准）；age 10-100 岁；sex 取 `male`/`female`/`none`；targetWeight 需落在 **BMI 18.5-24 的健康区间**内（不允许设成偏瘦或超重的目标）。仅在用户提供了相应信息时填写；超出范围的值会被 App 夹紧到边界。填写 age 与 sex 后，App 会用 Mifflin-St Jeor 公式算出 BMR/TDEE 得到更准的热量目标；targetWeight 与当前体重之差决定盈余（增肌 +12%）或缺口（减脂 −20%）。
- **exercises**（可选，≤20 个）：只列**内置库没有**的动作。字段：
  - name：必填，≤20 字，与内置动作重名会被忽略并复用内置动作。
  - fig：动作示意图标枚举：`squat | pushup | fly | raise | dead | row | curl | core | bridge | stretch | rest`，非法值自动降级为通用图标。
  - part：部位枚举：`胸 | 肩 | 背 | 臂 | 腿 | 臀 | 核心 | 有氧 | 恢复`，非法值归入「核心」。
  - equip ≤10 字（如 自重/哑铃/弹力带）；sets ≤20 字（如 `3 × 12`、`3 × 40 秒`）；points ≤120 字动作要点。
- **plans**（建议 1 套）：name ≤16 字；`dir`（可选）取 `增肌`/`减脂`/`维持`，用于和用户目标方向比对并在不符时提醒；
  days 恰好 7 项（周一→周日），每项 `title` ≤10 字、
  `exNames` 为动作名数组（先引用内置动作名，内置没有的放进 exercises）；每天 4-5 个动作为宜。
- **meals**（可选）：3-6 餐；kcal/pro 为每公斤体重系数（热量 kcal/kg/天、蛋白 g/kg/天，
  安全区 kcal 20-45、pro 1.2-2.5，越界会被夹紧）；wcost 为 60kg 成人每周采购参考价（元）；
  rows 每行 `[食物, 分量, 蛋白质]`，蛋白质为 `—` 表示不计。
  App 会按 kcal 系数**推断该方案的方向**（≥32 增肌 / ≤28 减脂 / 中间为维持）用于匹配提醒，无需额外字段。
  折算方式：`pro` 按 `体重 × pro` 折算，但 App 会按目标方向自动抬高下限
  （减脂 ≥1.8g/kg 防掉肌，增肌/维持 ≥1.5g/kg），所以填 1.5 也是安全的；`kcal` 系数是**回退值**——
  一旦 settings 里给了 age 与 sex，App 就改用 Mifflin-St Jeor 的 BMR/TDEE 计算热量目标
  （此时 kcal 系数不参与），并据此等比缩放份量。

## 安全护栏（必须遵守）

1. 遵循渐进超负荷：选择「能标准完成目标次数、最后 2-3 次接近力竭」的重量，不指定具体 kg 数。
2. 新手前两周强度减半；每周至少 1 个休息日（轻度活动：拉伸+散步）。
3. 用户提及伤病（腰/膝/肩等）时，规避相关负重动作，改用低冲击替代并注明。
4. 减脂目标蛋白 ≥1.8g/kg 防掉肌；热量缺口温和（App 按 TDEE 的 −20% 计算，约 -300~600 kcal/天）。
5. 不输出医疗建议；输出末尾附一句「AI 定制仅供参考，不构成医疗建议」。

## 幂等性

导入是幂等的：动作按名字复用；**同名计划**、**同名 label 的饮食方案**重复导入时为「更新」而非重复新增（保持原位置与启用状态）。用户可以反复导入迭代修正的方案，不会产生重复副本。
